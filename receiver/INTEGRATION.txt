MirrorMe background receiver
===========================

Executable: engine\mirrorme-receiver.exe
Build: .\scripts\build-receiver.ps1
Optional compiler selection:
  .\scripts\build-receiver.ps1 -ToolchainDirectory C:\Strawberry\c\bin

The executable is a normal Windows console-subsystem process with no Qt,
control window, system-tray icon, Bluetooth beacon process, or elevation.
Launch it with CREATE_NO_WINDOW, redirected stdout/stderr, and a redirected
stdin PIPE held open while the receiver should run. Only GStreamer's normal
video sink can create a video window when a client supplies video.
The separate output is titled "MirrorMe - iPhone screen". Both title-bar
and taskbar icons come from the receiver's embedded MirrorMe resource; no
neighboring application executable is needed in downloaded runtime caches.
The frame watcher brands only this process's visible captioned windows and
checks again after reconnects or renderer-created replacement windows.
Cross-thread window messages have a deadline, so a stuck graphics window
cannot indefinitely block the receiver's control loop.

Normal UxPlay arguments are converted from the Windows UTF-16 command line
to UTF-8 and forwarded unchanged. Example:
  engine\mirrorme-receiver.exe -n "MirrorMe" -nh -d 1 -vs d3d11videosink

The receiver puts its own executable directory first on its process-local
DLL search path and PATH. GST_PLUGIN_PATH defaults to the adjacent
lib\gstreamer-1.0 directory, and an explicitly supplied GST_PLUGIN_PATH is
honored. System plugin directories are disabled. GST_REGISTRY_FORK defaults
to "no", avoiding an external plugin-scanner process. The supervisor should
set GST_REGISTRY to a writable application-specific cache file.

Lifecycle protocol
------------------
All stdout and stderr are unbuffered UTF-8. Read both streams continuously.

  MIRRORME_RECEIVER_READY port=<decimal TCP port>

This complete stdout line is emitted ONLY after renderer initialization,
successful TCP listening, and successful asynchronous Bonjour registration
callbacks for BOTH _raop._tcp and _airplay._tcp. Each registration has a
10-second deadline and is interruptible by a stop request. Bonjour must
already be running; the adapter does not install or start that service.
The line means local initialization/registration succeeded, NOT that an
iPhone has discovered or connected to this computer, or that a firewall
permits peer traffic.

Video lifecycle:
  MIRRORME_VIDEO_RECEIVED
  MIRRORME_STREAMING
  MIRRORME_VIDEO_STOPPED

VIDEO_RECEIVED means appsrc accepted an encoded packet. STREAMING is emitted
only after a real GstVideoSink reports at least one rendered frame. Codec
selection, a PLAYING pipeline, HLS setup, and a fakesink cannot claim screen
mirroring. The watcher holds a pipeline reference and is removed before
renderer teardown. Decoder, buffer-push, and display failures are explicit
MIRRORME_RECEIVER_ERROR lines. Closing the output window is a normal stop.
Production libuxplay may prefix errors with "*** ERROR: "; the supervisor
recognizes that exact prefix, as well as unprefixed adapter errors.
MIRRORME_RECEIVER_WARNING reports a recoverable problem in activity without
stopping video or mislabeling it as a Wi-Fi failure.

Video synchronization stays enabled. The timestamp callback preserves each
packet's original client timestamp, mapping it to PC time once on each
retry. A frame older than pipeline startup can require a clock correction;
applying the full offset again to an already-mapped timestamp instead
schedules video far into the future. The timing regression exercises this
production callback, not just the decoder.

Do NOT treat these original upstream messages as readiness:
  UxPlay 1.73.6: An Open-Source AirPlay mirroring and audio-streaming server.
  Initialized server socket(s)
  register_dnssd: advertised AirPlay service with "Features" code = ...

The original registration log is debug-only. The published upstream passed
NULL callbacks to DNSServiceRegister, ignored raop_start_httpd failures, and
called cleanup()/exit(0) on startup failures. The maintained patch fixes
those integration problems and sends error/warning logs to stderr.
Bluetooth-only fallback cannot claim readiness: both DNS-SD registrations
are required even if upstream's -ble flag is supplied.

To stop, write ASCII "stop\n" (CRLF also accepted) and flush stdin, OR close
the write end of the inherited stdin pipe. Keep stdin open otherwise.
The reader recognizes only complete "stop" lines; oversized/unknown lines
are ignored. The monitor does not read an interactive console or disk file;
manual console launches may use Ctrl-C. Startup errors never wait for stdin.

  MIRRORME_RECEIVER_STOP_REQUESTED reason=stdin-command
  MIRRORME_RECEIVER_STOP_REQUESTED reason=stdin-eof
  MIRRORME_RECEIVER_STOPPED

Stopping only sets an atomic flag. The receiver's own thread performs
network unregistration and GStreamer destruction; the input reader never
destroys objects concurrently with callbacks. The running GLib loop checks
the flag every 100ms. Allow a shutdown grace period for protocol threads to
join before any supervised force-kill fallback.

Failures return nonzero and report on stderr, including original messages:
  *** ERROR: Could not initialize dnssd library!: error ...
  *** ERROR: No DNS-SD Server found (DNSServiceRegister call returned ...)
  *** ERROR: dnssd_register_raop failed with error code ...
  *** ERROR: dnssd_register_airplay failed with error code ...
  *** ERROR: Could not start the AirPlay TCP listener
  MIRRORME_RECEIVER_ERROR: ...

Registration timeout is Apple's kDNSServiceErr_Timeout (-65568).
A missing statically imported DLL prevents entry into main; Windows reports
a loader exit status instead of allowing the adapter to print diagnostics.
The supervisor must handle process-start/early-exit failures, not only logs.

Offline validation
------------------
  --version     Prints adapter version and exact source commit; no listener.
  --self-test   Loads bundled libraries and required plugin factories without
                creating video/audio pipelines or network registrations.
  -help         Standard UxPlay help; no listener.
  --media-self-test             Decodes H.264 through the production renderer
                               into a test sink; must NOT report STREAMING.
  --media-self-test-software    Same check with avdec_h264 selected explicitly.
  --media-self-test-window      Uses the automatic Windows video sink; must
                               render 30 frames, report STREAMING, and have
                               the MirrorMe title and both embedded icons.
  --media-self-test-timing      Synchronized production timestamp callback;
                               buffered first frame, client clock behind PC.
  --media-self-test-timing-negative
                               Same regression with client clock ahead.
  --media-self-test-timing-on-time
                               Normal first frame with no startup correction.
  --media-self-test-timing-window
                               Buffered timestamp regression in a real,
                               branded Windows video window.
  --media-self-test-invalid     Intentional pipeline failure; must exit 1.

Success from --self-test begins MIRRORME_RECEIVER_SELF_TEST_OK and MUST NOT
be interpreted as receiver readiness. It checks H.264, AAC, ALAC, conversion,
audio/video sinks, libplist, OpenSSL, and the required Bonjour API exports.
Plugin DLLs are explicitly loaded; cached registry entries alone cannot
make the test pass. No pipeline or renderer is instantiated by this check.
The build script tests version, plugins, help, Unicode argument forwarding,
and nonzero/stderr handling for invalid options, missing explicit
configuration files, and an empty plugin directory. Its probe
PATH excludes the development compiler and SDK to detect missing bundle
dependencies. It also checks the PE console subsystem and absence of Qt
imports. No physical iPhone, audio playback, or end-to-end mirroring is
claimed by these offline checks.

The original blue 320x480 H.264 fixture is embedded at build time. It was
generated, not downloaded:
  ffmpeg -f lavfi -i color=c=0x1671c5:s=320x480:r=30 -frames:v 1 -c:v libx264
    -preset veryfast -tune zerolatency -profile:v baseline -pix_fmt yuv420p
    -x264-params keyint=1:repeat-headers=1 -f h264 receiver\tests\blue-frame.h264
The media probes submit a bounded number of frames and check decoded sink
statistics, with a separate no-input interval that must not report mirroring.
Timing probes also check that the callback leaves the packet's client
timestamp unchanged. All timing modes run in the normal native build.
Use -TestVideoWindow to include the two real-window checks when building
on an interactive Windows desktop; they display only a generated blue frame.

The upstream GPL license and component licenses are preserved under

receiver\vendor\libuxplay is the PRISTINE pinned checkout.
receiver\patches\windows-receiver.patch contains the Windows integration
changes; receiver\patches\video-lifecycle.patch adds frame-based reporting.
receiver\patches\video-timing.patch fixes repeated timestamp conversion.
The script archives the exact commit, applies these maintained patches to
build\receiver\libuxplay, and builds that copy. Do not edit the pristine
checkout; update the maintained patch for future native changes.
receiver\resources\mirrorme.ico and receiver\receiver.rc.in supply the
standalone receiver's application icon and Windows version information.

The public Windows preview carries this executable but no third-party DLLs.
First-run setup downloads the pinned upstream runtime only after user consent.
The matching source ZIP includes receiver\libuxplay.bundle; the build script
clones it at the exact pinned commit. Otherwise it fetches that commit from
the public upstream repository. It also downloads the hash-pinned runtime
when building in a fresh development checkout so offline probes can run.

Required developer tools: x64 MinGW-w64 UCRT C/C++ compiler, CMake >= 3.24,
Ninja, Git, PowerShell, and Windows tar with zstd support. Validated with
Strawberry's GCC 13.2.0 x64-ucrt-posix-seh, CMake 3.29.2, and Windows
PowerShell 5.1 (also compatible with PowerShell 7). No MSYS2 install,
Qt SDK, administrator rights, or global package updates are required.
There is deliberately no -march=native, so the binary is not tuned to this
build machine's optional CPU instructions.

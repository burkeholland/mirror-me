Contract and supported audio
----------------------------
ct=1: little-endian signed PCM (16/24-bit, mono/stereo); rates 8/16/24/32 kHz
      at 16-bit and 44.1/48 kHz at 16/24-bit, according to audioFormat.
ct=2: ALAC 44.1/48 kHz, stereo, 16/24-bit.
ct=4: AAC-LC 44.1/48 kHz stereo, 1024 or 960 samples/access unit.
      Raw MPEG-4 access units use negotiated ASC. A single unprotected ADTS
      frame is also accepted after its profile/rate/channels/length are checked;
      it must use 1024 samples. Concatenated or CRC-protected ADTS is rejected.
ct=8: raw AAC-ELD AOT39, 480 or 512 samples/access unit; stereo 44.1/48 kHz
      and mono 16/24/44.1/48 kHz. This is ELD core audio without LD-SBR,
      resilience or arbitrary ELD extensions, matching UxPlay's AirPlay ASC.
      44.1 kHz stereo/480 uses f8e85000, NOT an AAC-LC/ADTS header.

audioFormat is either zero (legacy 44.1 kHz stereo/16-bit default) or exactly
one compatible negotiated bit, not a capability mask. A zero samples_per_packet
selects 352 for ALAC/PCM, 1024 for LC, 480 for ELD. Unknown ct/format/depth/
frame sizes fail explicitly rather than falling back to a different codec.
At most 65536 encoded bytes, 4096 output frames and 2 channels per decode.
FFmpeg allocation callbacks independently constrain actual channel/sample
buffers; AAC needs a bounded 2048-frame internal working buffer even for ELD.

The caller supplies one decrypted, RTP-stripped codec packet at a time, in
playback order. The decoder does not strip AirPlay/RTP/encryption headers.
PCM output is signed16 and interleaved; 24-bit samples are downconverted, not
reinterpreted. Output remains owned by the decoder until the next decode,
flush or destroy. Different instances can be created/destroyed concurrently;
decode/flush/destroy of one instance require a single consumer.
Each error clears the returned frame and reports a concrete error message.
Flush discards and lazily recreates the codec context, including AAC overlap,
configuration and PNS state. Any reinitialization failure is reported by the
next decode, not silently swallowed by the void flush API.

Building and testing (developer only)
------------------------------------
PowerShell 7, the pinned Strawberry GCC 13.2.0 UCRT toolchain, GNU Make and Git
Bash are required. No packages are installed by the script:
  .\scripts\build-audio-codecs.ps1 -Test
  .\scripts\build-audio-codecs.ps1 -Rebuild -Test

Include: build/native-audio/install/include and native/include
Compile: native/audio_decode.cpp as C++17
Static link order:
  libavcodec.a libavutil.a -lbcrypt -lole32 -luuid
  -static -static-libgcc -static-libstdc++
The test executable is build/native-audio/audio-tests.exe. The script checks
its PE import table against Windows OS DLL names and writes
build/native-audio/audio-tests-imports.txt. The host executable must perform
its own import inspection after combining protocol, video and audio modules.

Test-only code and original media
--------------------------------
See native/tests/audio_fixtures/NOTICE.txt, provenance.json and
LIBXAAC-LICENSE.txt. Real AAC-ELD fixtures are generated from original sine
waves with the Apache-2.0 Ittiam libxaac encoder, built from pinned source with
a documented core-only ELD configuration patch. libxaac is NOT linked into
the production application. There is no libfdk dependency.
